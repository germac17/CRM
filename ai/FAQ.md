# FAQ - Часто задаваемые вопросы

## 🚀 Установка и запуск

### Q: Какая версия Python требуется?
**A:** Python 3.9 или выше. Проверить версию: `python --version`

### Q: Нужно ли устанавливать Node.js для AI-сервиса?
**A:** Нет, AI-сервис написан на Python и не требует Node.js. Node.js нужен только для backend и frontend.

### Q: Можно ли запустить AI-сервис отдельно от остальной системы?
**A:** Да! AI-сервис полностью независим. Просто запустите:
```bash
cd ai
python setup.py
python demo.py  # для демонстрации
python app.py   # для API
```

### Q: Сколько времени занимает первая установка?
**A:** 5-10 минут в зависимости от скорости интернета (загружаются ML модели ~200MB).

## 🔧 Настройка

### Q: Как изменить порт AI-сервиса?
**A:** Отредактируйте `config.py`:
```python
API_PORT = 8001  # Измените на нужный
```
Или через переменную окружения:
```bash
export API_PORT=9000
python app.py
```

### Q: Как сделать оценку более строгой/мягкой?
**A:** Измените пороги в `config.py`:
```python
CATEGORY_THRESHOLDS = {
    "suitable": 8.0,      # Было 7.0 - более строго
    "conditional": 5.0,   # Было 4.0
}
```

### Q: Как добавить новые синонимы навыков?
**A:** Отредактируйте `utils/synonyms.py`:
```python
SKILL_SYNONYMS = {
    "ваш_навык": ["синоним1", "синоним2"],
    # ... остальные
}
```

### Q: Можно ли изменить веса компонентов оценки?
**A:** Да, в `config.py`:
```python
WEIGHTS = {
    "skills": 0.50,      # 50% вместо 40%
    "semantic": 0.20,    # 20% вместо 30%
    "experience": 0.20,
    "education": 0.10,
}
```

## 📊 Использование

### Q: Как система оценивает кандидатов?
**A:** Система использует 4 компонента:
1. **Навыки (40%)** - совпадение с требованиями
2. **Семантика (30%)** - понимание контекста
3. **Опыт (20%)** - соответствие лет опыта
4. **Образование (10%)** - наличие требуемого образования

Итоговая оценка: 1-10 баллов

### Q: Что означают категории?
**A:**
- 🟢 **Подходящие (7-10)** - приглашаем на собеседование
- 🟡 **Условно подходящие (4-6)** - рассматриваем при отсутствии лучших
- 🔴 **Не подходящие (1-3)** - отклоняем

### Q: Что такое "confidence" и "needs_review"?
**A:**
- **Confidence (0-1)** - уверенность модели в оценке. Низкая уверенность (<0.7) означает, что TF-IDF и BERT сильно расходятся.
- **needs_review** - флаг для HR: рекомендуется ручная проверка

### Q: Понимает ли система синонимы?
**A:** Да! Система распознает:
- Python = Python3 = питон
- JavaScript = JS = ES6
- Kubernetes = K8s
- PostgreSQL = Postgres = PG
- И еще 100+ синонимов

### Q: Как система извлекает опыт работы из резюме?
**A:** Ищет паттерны типа:
- "5 лет опыта"
- "Опыт работы: 3 года"
- "3+ years of experience"

## 🐛 Решение проблем

### Q: Ошибка "ModuleNotFoundError: No module named 'spacy'"
**A:**
```bash
# Убедитесь, что виртуальное окружение активировано
.venv\Scripts\activate  # Windows
source .venv/bin/activate # Linux/Mac

# Установите зависимости
pip install -r requirements.txt
```

### Q: Ошибка "Can't find model 'ru_core_news_md'"
**A:**
```bash
python -m spacy download ru_core_news_md
```

### Q: Сервис очень медленно работает
**A:** 
1. Проверьте, что используется виртуальное окружение
2. Убедитесь, что установлены все зависимости
3. Для ускорения можно использовать только TF-IDF (в `config.py` отключите BERT)
4. Добавьте кэширование результатов (Redis)

### Q: "Connection refused" при обращении к API
**A:**
1. Убедитесь, что сервис запущен: `python app.py`
2. Проверьте правильность порта: http://localhost:8001
3. Проверьте firewall

### Q: Низкая точность оценок
**A:**
1. Добавьте больше синонимов в `utils/synonyms.py`
2. Настройте фильтры и веса под вашу специфику
3. Соберите feedback от HR и дообучите систему
4. Используйте более качественные описания вакансий

### Q: Система не находит навыки в резюме
**A:**
1. Убедитесь, что навыки указаны в секции "Навыки" или "Skills"
2. Добавьте специфичные для вашей сферы навыки в `nlp_service.py`
3. Используйте парсинг файлов (PDF/DOCX) вместо текста

### Q: Ошибка при парсинге PDF/DOCX
**A:**
```bash
# Убедитесь, что установлены библиотеки
pip install PyPDF2 python-docx
```

## 🔌 Интеграция

### Q: Как интегрировать с существующим backend?
**A:** AI-сервис предоставляет REST API. Пример:
```javascript
// В вашем backend
const response = await fetch('http://localhost:8001/api/match/batch', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    vacancy_id: 'vac-001',
    auto_save: true
  })
});

const matches = await response.json();
```

### Q: Можно ли использовать с другими языками программирования?
**A:** Да! AI-сервис - это HTTP API. Можно использовать с любым языком:
- Python: `requests`
- JavaScript: `fetch` / `axios`
- Java: `HttpClient`
- PHP: `cURL`
- Go: `net/http`

### Q: Как добавить авторизацию к API?
**A:** Добавьте middleware в `app.py`:
```python
from fastapi import Security, HTTPException
from fastapi.security import HTTPBearer

security = HTTPBearer()

async def verify_token(credentials = Security(security)):
    if credentials.credentials != "your-secret-token":
        raise HTTPException(status_code=401)

@app.post("/api/match/analyze", dependencies=[Security(verify_token)])
async def analyze_match(...):
    ...
```

### Q: Поддерживается ли пакетная обработка?
**A:** Да! Endpoint `/api/match/batch` обрабатывает до 500 кандидатов за раз.

## 📈 Производительность

### Q: Сколько времени занимает анализ одного кандидата?
**A:** 0.5-2 секунды в зависимости от:
- Длины резюме
- Использования BERT (медленнее) vs TF-IDF (быстрее)
- Мощности сервера

### Q: Можно ли ускорить обработку?
**A:**
1. **Используйте только TF-IDF** (в 3-5 раз быстрее)
2. **Добавьте кэширование** (Redis)
3. **Используйте асинхронную обработку** (Celery)
4. **Увеличьте ресурсы сервера** (CPU/RAM)
5. **Используйте GPU** для BERT (10x ускорение)

### Q: Сколько кандидатов можно обработать одновременно?
**A:** 
- По умолчанию: до 500 за запрос
- Можно увеличить в `config.py`: `MAX_CANDIDATES_PER_REQUEST`
- Для больших объемов используйте фоновую обработку

## 🎓 Обучение и данные

### Q: Нужно ли обучать модель?
**A:** Нет! Система работает "из коробки" используя:
- Предобученную spaCy модель для русского языка
- Предобученную BERT модель (multilingual)
- Словари синонимов
- Эвристические правила

Но вы можете дообучить на своих данных для повышения точности.

### Q: Как система обучается на моих данных?
**A:** Базовая версия не сохраняет обучение. Для ML:
1. Собирайте feedback от HR (правильные/неправильные оценки)
2. Сохраняйте в датасет
3. Дообучайте модели на ваших данных
4. Используйте A/B тестирование

### Q: Где хранятся данные?
**A:** По умолчанию в JSON файлах:
- `backend/data/user-{id}-candidates.json`
- `backend/data/user-{id}-vacancies.json`
- `backend/data/user-{id}-matches.json`

Для production рекомендуется PostgreSQL или MongoDB.

## 🌍 Язык и локализация

### Q: Работает ли система с английским языком?
**A:** Частично. Текущая версия оптимизирована для русского:
- spaCy модель: `ru_core_news_md`
- Синонимы: в основном русские/английские термины

Для полной поддержки английского:
```bash
python -m spacy download en_core_web_md
```
И измените `config.py`:
```python
SPACY_MODEL = "en_core_web_md"
```

### Q: Можно ли использовать для других языков?
**A:** Да! BERT модель - multilingual. Для лучшего качества:
1. Установите spaCy модель для вашего языка
2. Добавьте синонимы навыков
3. Настройте парсинг под форматы резюме в вашей стране

## 💼 Production

### Q: Готова ли система к production?
**A:** Базовая версия - для MVP/демо. Для production нужно:
- ✅ Добавить авторизацию
- ✅ Настроить мониторинг (Prometheus)
- ✅ Добавить логирование (ELK stack)
- ✅ Использовать БД (PostgreSQL/MongoDB)
- ✅ Добавить кэширование (Redis)
- ✅ Настроить rate limiting
- ✅ Добавить тесты (pytest)
- ✅ CI/CD pipeline
- ✅ Докеризация (уже есть Dockerfile)

### Q: Как развернуть на сервере?
**A:**
```bash
# Docker (рекомендуется)
docker-compose up -d

# Или вручную
cd ai
pip install -r requirements.txt
python -m spacy download ru_core_news_md
uvicorn app:app --host 0.0.0.0 --port 8001 --workers 4
```

### Q: Нужен ли GPU?
**A:** Нет, но желателен для:
- Ускорения BERT embeddings (10x)
- Обработки больших объемов (1000+ кандидатов)

CPU вполне достаточно для MVP и малых объемов.
